# 小橘遥控（Android 被控端）

在一台安卓手机（B）上装这个 App，开「待命」后，另一台设备（A，手机或电脑都行）就能发指令，用 B 的硬件：拍照、录音、定位、手电筒、震动、响铃、跑一条 shell。

两台设备之间不直接连，走小橘云盘当「信箱」：A 把指令写到云盘，B 轮询收到就执行，再把结果和照片写回云盘。所以不用在同一个网络，隔着城市也行；代价是有几秒延迟（轮询间隔 4 秒）。

## 为什么要开着 App、通知栏一直显示

安卓规定：App 要在后台用摄像头 / 麦克风 / 定位，必须是「前台服务」并且通知栏常驻一个通知。这个 App 就是这么做的——被远程使用时通知会写明「正在被远程使用：拍照」，动作也都记在 App 里。这是系统的要求，也是为了谁都能看出来它在被用。做不到锁屏后台偷偷开摄像头，也做不到看 / 控别人的整个屏幕，那是 iOS/Android 都不允许的。

## 装

1. 代码在 `langhua98/xiaoju-remote` 仓库的 `android/`（2026-11 从 meta-work 的 `src/xiaoju-remote-android/` 搬过来）。在 Actions 里手动运行 `.github/workflows/android.yml`（「Build 小橘遥控 apk」），它会在 GitHub 的 Ubuntu 机器上编译。
2. 编好的 APK 发布到本仓库的 Release「xiaoju-remote-android」，下载 `xiaoju-remote-latest.apk`。
3. B 手机：设置里允许「安装未知来源」，装上。App 名字叫「法莉娅」（0.16 起，图标是她的头像）。
   签名：0.16 起用固定密钥（在小橘云盘私有文件夹 `/小橘推送/签名/android-signing.json`，GitHub 编译时用 `XIAOJU_TOKEN` 取来签）。
   0.12～0.15 是在 GitHub 上编的临时签名，每个包都不一样，所以从这些版本升到 0.16 要先卸载一次；以后就能直接覆盖安装。

## 用

B 手机，打开 App（0.20 起界面简化了）：
- **云盘地址、令牌不用填**：地址固定，令牌编译时打进 App（GitHub secret `XIAOJU_TOKEN`）。本地编、没带令牌的包才会显示令牌框。
- **设备名**只能选 A、B、C、D，默认 A。控制端发指令时设备名写 `A`～`D`。
- **配对口令**默认 `0`，A 发指令时要带同一个口令，不对的指令会被拒绝。清空了也会回到 `0`。
- 点**授权硬件**，把相机 / 麦克风 / 定位 / 通知的权限都允许（想用哪个就给哪个）。
- 点**开始待命**。通知栏出现「小橘遥控 · 待命中」就对了。建议插着电、屏幕可以息屏，但别在系统里把 App 强制「省电 / 休眠」。

A 设备发指令，用 `scripts/遥控.py`：

```bash
export XIAOJU_TOKEN=xa_你的令牌
export XIAOJU_PAIR=0   # 默认就是 0，不设也行
python3 scripts/遥控.py A info
python3 scripts/遥控.py A photo --lens front   # 拍完照片下载到当前目录
python3 scripts/遥控.py A audio --seconds 8
python3 scripts/遥控.py A location
python3 scripts/遥控.py A torch --on
python3 scripts/遥控.py A ring --seconds 5      # 找手机：响铃
python3 scripts/遥控.py A shell --cmd "ls /sdcard"
python3 scripts/遥控.py A update               # 有新版本就下载、安装（0.19）
python3 scripts/遥控.py A update --check       # 只看有没有新版本
```

## 指令

| do | 参数 | 做什么 |
|----|------|--------|
| `info` | — | 型号、系统、电量 |
| `photo` | `lens`=back/front | 拍一张，JPEG 传回 |
| `audio` | `seconds` 1–60 | 录一段，m4a 传回 |
| `location` | — | 一次定位，经纬度 + 地图链接 |
| `torch` | `on` true/false | 开关手电筒 |
| `vibrate` | `ms` | 震动 |
| `ring` | `seconds` | 响铃（找手机） |
| `shell` | `cmd` | 在 App 沙盒里跑一条 shell（非 root，只有 App 自己的权限） |
| `video` | `transport`=ws、`room`、`codec`=h264/jpeg、`lens`、`width`、`fps`、`quality`、`audio` | 实时画面（走云盘的直播通道） |
| `video_set` | 同上加 `exposure`、`zoom`、`torch`、`flip`、`stamp` | 直播 / 侦测中调相机；`flip` 上下翻转（转 180°，手机倒装时用）、`stamp` 印日期时间（默认开），这两个记在手机上（0.17） |
| `monitor` | `on`、`sensitivity` 1–100、`regions` [[x,y,w,h]…]、`pre`、`post`、`notify`、`people`（只在认出人时提醒，0.12）、`eco`（省电侦测，0.14，默认开）、`duty`、`duty_on`、`duty_off`（间歇守望，0.18，默认开，看 2 秒歇 4 秒）、`cooldown`、`audio`、`upload`、`lens`、`width`、`fps`、`quality` | 移动侦测设置（只改给了的字段），回执带状态 |
| `monitor_status` | — | 侦测状态：今天几段、占多少空间、待备份、Telegram；`objects` 是能认东西时用的模型（空 = 认不了） |
| `events` | `limit`、`before` | 录好的事件（新的在前，带小图）；`labels` 是认出来在动的东西（「人×2、猫」） |
| `event_get` | `name` | 取一段录像：备份过的给云盘路径，5 MB 以内直接放回执，大的先传到云盘 |
| `event_delete` | `name` | 删手机上的一段（云盘备份不动） |

| `bench` | — | 模型测速（0.10）：几个能认人的小模型各跑一遍（1/2/4 核），有人看实时画面时再测直播帧率掉多少；大约 1 分钟 |

| `cancel` | `target`（要取消的那条指令的 id） | 打断一条还在做的慢指令（测速、录音…），替它回「已取消」 |

| `update` | `check`（只看不下载） | 查云盘「软件包」有没有新版本，有就下载、安装（0.19）。回执多 `version`、`build` |

### 云盘一传新包就自动更新（0.23）

- 往小橘云盘「软件包」文件夹传一个 `.apk`（workflow 自动传、自己手动传都行），服务端马上往待命手机的即时信箱放一条
  `{"do":"update_hint","name":…}`（xiaoju-cloud 的 `package_hint.go`）。手机收信时带 `&updates=android` 才会收到，iPhone 被控端不带。
- 这条只是提醒，不是指令：没有口令，也不回执。手机收到后马上查更新（不再等 6 小时），装之前照样核对包名、版本和签名。
  正在直播或录像时先不装，结束后马上装。6 小时一次的定时检查留着兜底（手机离线时传的包，上线 1 分钟后会查到）。
- 名字不规范的包（比如手动传的 `app-release.apk`）也认：先按规范名字比；没有更新的，再把没看过的包下载下来，
  让系统读里面的 versionCode 和构建号（0.23 起写在 meta-data `xiaoju.build` 里）。不比手机上新的按云盘文件 id 记下，下次不再下。
  同一个版本号想再推一次：手动编的包要把 versionCode 加 1（本地编的构建号是 0）；workflow 编的构建号会自己变大。
- root 安装改成脚本在后台跑：先复制到 `/data/local/tmp`（新系统 pm 读不了 App 自己的目录），`pm install -r`，
  看到 Success 等 3 秒用 root 把待命服务拉起来（`am start-foreground-service`，老系统 `am startservice`）。
  安装时系统杀掉法莉娅，脚本不会跟着死；`UpdateReceiver` 也还在，两边谁先拉起来都行。root 装不上才改成弹安装界面。
- 从 0.22 升到 0.23 还是走老办法（6 小时一次，或者发 `update` 指令）；0.23 以后就是一传就更新。

### 直播没画面：真正的原因（0.22）

- 在 S4 上用 `shell` 读 App 自己的系统日志（`logcat -d -v time Camera:V *:E`），每次开相机都是：
  `Camera-JNI: Callback buffer was too small! Expected 460800 bytes, but got 0 bytes!` 和
  `BufferQueue: dequeueBuffer: min undequeued buffer count (2) exceeded`。相机开着（`camera_opens` 在涨），预览回调却一次都没来（`callbacks` 是 0）。
- 原因：0.13 起为了省电，相机手里最多放一块缓冲区、快用到时才给（FramePacer）。三星 S4（4.2）相机手里一没有缓冲区，
  系统就把预览回调关掉、预览也卡住，之后再也不交画面：直播没画面（声音也跟着出不来）、侦测看不到东西、拍照「没截到画面」。
- 0.22：3 块缓冲区一直放在相机手里，每帧用完马上还；用不上的帧在 Java 这边丢掉（`FramePacer.due` 只管抽帧）。比 0.13 的做法多拷一些帧、多费一点电，但一直出画面。
- 4.2 的系统没有 grep：在手机上过滤日志用 logcat 自己的过滤（`Tag:级别 *:S`）。

### 直播没画面、手机卡（0.21）

- 0.20 没修好，还更糟：S4 上直播、手电、声音都不行，手机很卡。原因推测是 0.18 加的「在开着的相机上换对焦方式」
  （守望时定焦、直播时连续对焦）：S4 一换对焦预览就不出画面；0.20 加的「10 秒没画面就关掉相机重开」于是一直循环，
  相机一直被占（手电不行）、CPU 一直忙（手机卡）。
- 0.21：对焦一直是连续对焦，不在开着的相机上换（回到 0.17 的做法）；去掉关掉重开，只在 4 秒没画面时补一次缓冲区、记一行日志。

- 真正的原因（0.21 查到的）：这台 S4 的系统相机服务卡住了，开相机（`Camera.open`）一直不回来、也不报错，
  所以相机「开着」却一次都没开成（`monitor_status` 里 `camera_opens` 是 0）。重启手机就好。
  0.20 开相机 8 秒没回来就当失败、5 秒后再开，卡住的线程越堆越多，手机很卡。0.21 起所有开相机都走 `Camera.open`：
  上一次还没回来就不再开新的，直接回「系统相机服务卡住了，重启手机就好」（直播、拍照、手电都一样）；同样的错只记一次日志。

### 直播没画面（0.20 的修法，保留缓冲区补满）

- 0.18、0.19 的 bug：开直播、开始 / 结束录像时，相机要换帧率档和对焦方式（守望时定焦、直播时连续对焦）。
  S4 不让在预览中直接改，就停一下预览再开，可停预览时相机手里那块缓冲区收不回来；缓冲区一共两块，换两次就没了，
  相机开着却一帧都不交：直播「发出 0 帧」（声音照常）、拍照「相机正在用，没截到画面」，而且没有任何报错。
- 修法（`Camera.kt`）：改不了先只换帧率档；真要停预览，停完把缓冲区补满。再加一道保险：相机 4 秒没交一帧就补缓冲区；开相机 8 秒没开好当失败处理（以前会当成开好了空转）。处理画面出错也会记一行日志，不再一声不吭。

### 自动更新（0.19）

- 新安装包从哪来：`android.yml` 每次编好都传到小橘云盘 `/软件包/xiaoju-remote-android-<版本>-build<构建号>.apk`。
  构建号是 GitHub 的 run_number，编译时也写进 App（`BuildConfig.BUILD_NUMBER`，Gradle 参数 `-PbuildNumber`），
  手机比「版本号，再比构建号」，所以同一个版本重编一次也会更新。本地编的构建号是 0。
- 手机用自己的云盘令牌列 `/软件包/`，所以令牌要能读这个文件夹。读不了时 `update` 回执会说「云盘令牌读不了 /软件包」。
- 待命时自动查：开始待命 1 分钟后查一次，以后每 6 小时一次；正在录像或直播时等一等再查。0.23 起云盘一传新包就马上查（见上面）。
  0.20 起自动更新一直开着，不能关（App 里只留「检查更新」按钮）。
- 下载后先检查：包名一样、版本不更旧、签名和手机上装的一样（不一样系统也装不上，要先卸载）。
- 怎么装（`Updater.kt`）：
  - **手机有 root**（找得到 `su`）：`su -c pm install -r` 直接装，不用人点。第一次 root 管理器可能会问一下要不要允许。
  - **没有 root**：安卓不让普通 App 自己装，只能打开系统安装界面，要有人点一下「安装」。
    Android 10 以下直接弹出安装界面，10 以上只发一条通知「点这里安装」；Android 8 以上第一次还要允许法莉娅「安装未知应用」。
    自动更新对同一个新版本只弹一次，没人点也不反复弹，通知一直留着。
- 装好后系统发「自己被更新了」（`UpdateReceiver`）：删掉下好的安装包，更新前在待命就接着待命（点过「停止」的不会自己开）。
- `info` 回执多一行「法莉娅：0.19（构建 57）」，看手机上现在是哪一版。
- 从 0.18 或更早的版本升到 0.19 要手动装一次，0.19 以后就能自动更新了。

### 同时收好几条指令（0.11）

- 收件循环只管分发，马上接着收：快的（`info`、`torch`、`vibrate`、`monitor`、`monitor_status`、`events`、`event_delete`、`cancel`）
  走单独一条线，慢的（拍照、录音、定位、测速、开直播…）最多 3 条一起跑。一条慢的不会挡住后面的。
- 两条指令要用同一个相机 / 麦克风时，后来的马上回 `ok:false, busy:true`（「相机正在忙（正在拍照）」），不默默排队。
- 指令带 `"ack": true` 时，慢指令先回一条 `pending:true` 的回执（「收到了，正在拍照…」），做完再回正式的；不带就只回正式的（老版本照常）。

### 模型测速（0.10，C++）

- 0.20 起 App 界面上的「测模型速度」按钮删了，要测就从控制端发 `bench`。

- 推理用 ncnn（腾讯开源，BSD），C++ 代码在 `app/src/main/cpp/`。先跑 `scripts/build-ncnn-android.sh` 编好 ncnn
  （要 NDK r23c，最后一个支持 4.2 的），Gradle 自动找到 `/opt/ncnn/armv7`（或 `-Pncnn.dir=`）；找不到就不带 C++，测不了模型，别的照常。
- 只编 32 位 ARM（armeabi-v7a）。模型权重全用 0，只量速度；认得准不准在电脑上用真权重测。

### 上下翻转、日期时间戳（0.17）

- `flip`：画面转 180°。在相机这一层多转 180°，直播、录像（mov 的旋转）、侦测截图、拍照（`photo`）都跟着转；侦测区域也是按转正后的画面算的。
- `stamp`：左上角印 `yyyy-MM-dd HH:mm:ss`（白字黑边），直接改 NV21 的亮度，直播、录像、截图都带上（`TimeStamp.kt`）。
  每秒用安卓画一次字、算好像素位置，每帧只改几千个字节；先做移动侦测再印字，跳动的秒数不会被当成动静。
- 两个设置记在手机上（Prefs），小橘推送开始直播时会带上它们（`video` 指令里的 `flip`、`stamp`）。

### 省电（0.13、0.14）：电源管家

从底层管电：谁要用电谁去申请，用完放掉；相机传感器、帧拷贝、编码器、麦克风、CPU、网络都按需开。

**相机（Camera.kt、FramePacer）**
- 传感器帧率只选够用的最低一档（`LiveSettings.pickFpsRange`）：录像、直播最多 15 帧，就不让传感器跑 30 帧。
- 预览帧只拷我们要用的：相机手里最多一块缓冲区，只在下一帧快该用时才给（提前 30 毫秒），
  中间的帧在驱动里就丢了，不拷贝、不叫醒 Java。以前相机 30 帧全拷进来（640×480 一帧 460 KB），只用 10 帧。

**省电侦测（`monitor` 的 `eco`，默认开）**
- 守望（没动静）：传感器换到最低帧率档（不重开相机）、每秒只看 4 帧；编码器、麦克风关着；顺便留最近几帧（最多 3 秒、8 MB）。
- 录像（有动静 → 最后一次动静后 `post` 秒）：传感器回到正常档，编码器打开，先喂守望时留的几帧（录像从动静前一两秒开始，那一段每秒 4 帧），
  再接着录，麦克风也打开。录完回守望，内存里的旧录像清掉。
- 关掉 `eco` 就和以前一样：编码器一直开着，能录到动静前 `pre` 秒，最费电。

**装傻省电（0.18）：没动静时能关的都关，真有变化才干活**
- 间歇守望（`monitor` 的 `duty`，默认开，只在 `eco` 里有）：相机开 `duty_on` 秒（1～10，默认 2）看一看，没动静就关掉相机、
  放掉 CPU 锁，定一个闹钟，歇 `duty_off` 秒（1～60，默认 4）再开。歇着的时候 CPU 能睡、相机传感器断电。
  - 歇着的时候发生又结束的动静会漏掉，要一点不漏就 `{"do":"monitor","duty":false}`（回到相机一直开着的省电守望）。
  - 侦测的背景跨轮留着（`MotionDetector.pause`），一开相机两帧就能报，不用每轮重新学 2.5 秒；刚开相机 0.5 秒内曝光还在变，不看。
  - 背景还没学好、或者正看到一半的动静（连着两次才算），不歇。有动静、开始直播、要拍照、开手电、改设置时马上叫醒。
  - 老系统（Android 6 以下）用 `ELAPSED_REALTIME_WAKEUP` 闹钟叫醒（4.4 起用 `setExact`）；6 以上有 Doze，只关相机、不放 CPU 锁。
- 守望时不印时间戳：留下的几帧开始录时按拍下的钟点补印，录像、截图、直播照样带时间。
- 守望时对焦定在无限远：0.21 去掉了（S4 上换对焦会让预览停住），一直连续对焦。
- 麦克风、编码器守望时本来就关着（0.14）。

**耗电诊断（0.18）**：`monitor_status` 回执的 `status.power`，`info` 里也有一行。S4 读不到实时电流，就比这几个数：
- `cpu_awake_pct`（启动以来拿着 CPU 锁的比例）、`camera_on_pct`、`rest_pct`（间歇守望歇着的比例）、`camera_opens`、`camera_open_ms`（开一次相机多久）
- `fps_ranges`（这台手机支持的帧率档）、`fps_now`（实际设上的档）、`preview`、`focus`、`callbacks`（预览回调次数）、`looks`（侦测看了几次）
- `motion_to_rec_ms`（发现动静到开始录用了多久）、`battery_pct`、`battery_mv`、`battery_c`、`plugged`
- 电脑上看：`python3 scripts/遥控.py 设备名 monitor_status`；改设置：`python3 scripts/遥控.py 设备名 monitor --set '{"duty": false}'`

**CPU 和网络（Power、RemoteService）**
- `Power` 是计数的 WakeLock：相机开着、执行指令、备份录像、发提醒、认东西时才拿着；收指令的长轮询在等服务器回话时放掉，
  CPU 可以睡（数据一到 Wi-Fi 会把它叫醒）。只在 Android 6 以下这么做（6 以上有 Doze，照旧一直拿着）。
- 看门狗：2 分钟一次的闹钟。长轮询等了 70 秒还没回来（睡着时连接断了），就把连接断掉重来。
- WifiLock：锁屏后 Wi-Fi 不断（有的老系统默认休眠时断 Wi-Fi）。
- 只有收指令的长轮询复用连接（一轮接一轮，不用每 25 秒重新做 TLS 握手）；回执、上传每次都用新连接——
  0.13、0.14 让它们也复用，闲了几十秒的连接被运营商 NAT 悄悄掐掉，再拿来发回执要等到超时（拍照回执一分钟），0.15 改回来。
- 回执遇到 429、502～504 或网络断一下，隔 1.5 秒、3 秒再试，最多 3 次。用即时信箱时文件信箱 10 分钟才看一次。
- 电流读数是固定值（S4 一直报 1900 mA：电量芯片不测电流）时不显示，`info` 写「读不到实时电流」。

**看电耗在哪（PowerMeter）**
- 从 `/sys/class/power_supply/battery/current_now` 读实时电流（三星等很多手机普通 App 能读）。
- `info` 回执写：电流、屏幕亮不亮、侦测在哪一档；`monitor_status` 多了 `current_ma`、`stage`（off / watch / record）、`eco`。
  小橘推送的侦测页状态行会显示「省电守望中 · 电流约 xxx mA」。

### 认出动的是什么（0.12，C++）

- 有动静时用 FastestDet（dog-qiuqiu，BSD 3-Clause，352×352，COCO 80 类）认一下，模型在 `assets/models/`（大约 0.5 MB），
  C++ 在 `cpp/fastestdet.cpp`、`cpp/detector_jni.cpp`，Kotlin 在 `ObjectDetector.kt`。只用 1 个核、后台优先级，S4 上大约 90 毫秒一张。
- 只在有动静时跑：新事件开始认一次，录的过程中每 1.5 秒再认一次（后进来的人）。
- 只留会自己动的（人、车、动物），而且框里正好有格子变了；床、椅子、停着的车不算。
- 认出来的写进提醒（「有动静：人×2」）和事件列表的 `labels`，截图和小图上框出来、写上名字。
- `people: true` 时只在认出人时发提醒（别的动静照样录）；安装包没带 C++ 或者模型读不了，就照常提醒。
- 没编 ncnn（找不到 `/opt/ncnn/armv7`）的安装包认不了东西，只有移动侦测，别的照常。
  GitHub 的 workflow 会先编好 ncnn（缓存起来），编出来的安装包一定带 C++，不带就报错。
- 认得对不对：`sh tests/detector/run.sh` 在电脑上用同一份 `fastestdet.cpp` 和模型认几张照片（宇航员、两个人、猫、咖啡杯），
  BGR 和手机相机的 NV21 两条路都要认对，个数也要对（同一个人的全身框和半身框只算一个）。workflow 编安装包前也跑这个。

### 移动侦测（0.8）

- 侦测在手机上跑：亮度缩成 32×24 格和背景比，整体变亮变暗不算，连续两次才算有动静。
- 有动静就录 H.264 + 声音，包括动静前 `pre` 秒（内存里一直留着），最后一次动静后再录 `post` 秒；存成 .mov
  （App 的外部存储目录 `Android/data/com.langhua98.xiaoju.remote/files/events/`，超过 3 GB 删最旧的）。
- 慢慢备份到云盘 `/小橘推送/遥控/<设备名>/录像/<日期>/`：一次一段、歇 1 分钟、限速 128 KB/s，有人看直播时不传。
- Telegram 提醒经云盘服务端的机器人发（`POST /api/agent/v1/notify`）：在 Telegram 里给那个机器人发一句 `/start` 就能收到。
- 侦测时手机要一直插电；相机开着时拍照是从画面截一张。

## 云盘上的文件夹

```
/小橘推送/遥控/<设备名>/
  收件/   A 写指令（<id>.json）
  回执/   B 写结果（<id>.json）
  文件/   B 传照片 / 录音（<id>-photo.jpg 等）
```

B 只按 id 记「处理过的指令」，不删收件箱里的文件。时间长了收件 / 回执会攒下来，A 端或定时任务可以自己清。

## 还没做 / 做不到

- 没有端到端加密：文件在云盘上是明文，安全全靠云盘令牌和配对口令，令牌别外传。
- 没有远程看屏幕 / 远程点屏幕——系统不允许普通 App 这么做。实时画面只能看摄像头（小橘推送「看对方的实时画面」）：
  走云盘的 WebSocket 直播通道，优先用手机硬件 H.264 编码，带声音同步，直播中能换镜头、调参数。
- 指令走即时信箱（长轮询，一般不到 1 秒）；服务端太旧没有即时信箱时退回文件信箱，会慢几秒。
